# 架构与容量边界

## 组件

- FastAPI Web：登录、脱敏查询、导入接收、任务创建和设置管理。
- PostgreSQL：账号密文、任务、策略和审计事件的唯一持久状态。
- Worker：单实例领取任务，分批导入、刷新、体检、调度和历史清理。
- Nginx：HTTPS、请求体上限、登录入口限速和受信任代理头覆盖。

Web 与 Worker 不通过内存队列通信。任务先提交数据库，Worker 使用行锁领取；进程退出后，`running` 任务在单 Worker 重启时恢复为 `queued`。

## 数据保护

- AES-GCM 每次写入使用随机 96 位 Nonce，并验证密文完整性。
- 邮箱精确检索使用 HMAC，不保存明文邮箱索引。
- 列表接口只返回脱敏邮箱、状态和时间信息。
- 导入文件使用不可预测 UUID 文件名与仅服务账户可读权限。
- 导入完成、取消或失败后删除临时文件；维护任务清理遗留的孤儿文件。
- OAuth 错误入库前会清除 Token、Bearer 凭据和邮箱明文。

## 大数据路径

- 账号列表使用 `id > cursor ORDER BY id LIMIT n`，不会随着页码加深而扩大扫描距离。
- 全量/到期任务在创建时记录最大账号 ID，避免把任务开始后新导入的数据无限卷入。
- Worker 每批最多读取 `WORKER_BATCH_SIZE` 个账号，导入每批最多解析 `IMPORT_BATCH_SIZE` 行。
- 导入单行有硬上限，避免无换行超大文件导致一次性内存膨胀。
- 仪表盘账号状态通过一次条件聚合完成，活跃任务使用独立索引查询。
- 审计和已结束任务按保留天数清理，避免长期无限增长。

精确统计仍需要数据库工作量，百万级数据应使用足够的 PostgreSQL 缓存与磁盘 IOPS，并根据外部限流逐步调低并发。不要把“支持游标分页”理解为任意低配置机器都能无上限承载数据。

## 一致性

- Refresh Token 只有在 OAuth 返回成功后才会替换。
- 每个批次在数据库事务中更新账号结果与任务进度。
- 任务 Heartbeat 每 60 秒更新，避免长时间外部请求看起来像僵死任务。
- 删除账号与正在执行的任务可能并发；Worker 会跳过已删除记录，任务统计可能因此少于创建时快照总数。
